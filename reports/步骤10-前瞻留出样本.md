## 5. Paper live 引擎

同一条代码路径既跑历史验证、也跑未来实盘观察，唯一差别是 root 与日期。

```
读取最新可用交易日
  → 结掉上一次挂起的订单
  → 数据完整性 + PIT 审计
  → 计算截至当日可获得的全部 feature
  → 跑冻结模型 → 预测
  → 非调仓日：HOLD / monitoring snapshot
  → 调仓日：目标组合 → 下单 → 模拟 T+1 开盘成交 → 更新 paper portfolio
  → 落盘（append-only）
```

| 项 | 值 |
|---|---|
| 初始本金 | 500,000 CNY |
| 调仓 | 月度 last_trading_day |
| Top-K | 20 |
| 目标仓位 | 95%（5% 现金缓冲） |
| 手数 | 100 股整数倍 |
| 执行 | T 收盘信号 → **T+1 开盘**成交 |
| 成本 | 与 strategy_v1 同一模型（逐项同参，有测试断言） |

### 三个关键机制

**挂单**：当天收盘后运行时 T+1 还没开盘，成交价不存在。订单挂起
（`state/pending_orders.json`），下次运行按 T+1 开盘价成交。
不这么做的话，实盘每次调仓信号都会"报出去但永远不成交"。

**按日幂等**：同一天重跑 = 无操作（直接返回已记录的 results）。
调度器重复触发不会把账户交易两次。

**现金守卫**：下单按 T 收盘价算、成交在 T+1 开盘。跳空高开时实际花费
会超过计划金额 —— 钱不够就减量（按整手）或不下单，绝不透支。

## 6. append-only 与 revision

| 规则 | 实现 |
|---|---|
| 不可覆盖 | 内容不同即 `PermissionError` |
| 不可回填 | 新写入日期不得早于已记录的最大 forward 日期 |
| revision 需理由 | `allow_revision=True, reason="..."`，旧版本保留，`revisions.jsonl` 留痕 |
| `created_at` 不参与比较 | 否则同一天重跑必然产生 revision |

## 7. 监控：只观察，不反馈

| 类型 | 检查 |
|---|---|
| strategy drift | config / model / feature pack 的 sha256 vs 冻结值 |
| model drift | 预测分布（均值/标准差/偏度）相对历史基线的 z 距离 |
| concentration | Top-1 预测分相对截面的 z |
| news drift | 新闻因子分布相对历史基线的位移 |
| data drift | 股票数 / 缺失率 / 覆盖率的相对变化 |

9 类告警（`PIT_FAILURE`、`STRATEGY_DRIFT`、`MODEL_DRIFT`、
`CONCENTRATION_WARNING`、`DRAWDOWN_ALERT`、`ABNORMAL_TURNOVER`、
`IC_NEGATIVE_STREAK`、`DATA_QUALITY_WARNING`、`STRATEGY_UNFROZEN`）
**只产生 WARNING**，绝不自动修复、绝不自动减仓。

`tests/forward/test_alerts.py` 断言告警文本里不得出现任何下单动作。

### 样本不足时不给结论

- 前瞻窗口没走完 → **NA**，不是 0（填 0 会把"还不知道"伪装成"收益为零"）
- 净值 < 60 天 → 不年化、不算 Sharpe
- 年度不足 230 个观测日 → 标记 `INCOMPLETE YEAR`，绝不对短样本年化
