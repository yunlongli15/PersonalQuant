## 关键决策记录

1. **日线基线用 Qlib 数据包**（chenditc/investment_data 2026-09-04，官方
   README 推荐源，STEP 1 已落地到 qlib_data/）。全市场导入 canonical 层。
2. **东财快照 API（push2）被 WAF 封禁**：估值快照改用**腾讯行情排行 API**
   （单次 ~24 页请求全市场；pe_ttm/pn(PB)/zsz/ltsz/hsl 字段已与已知股票
   公开值核对一致）。`ps`（市销率）该源缺失 → canonical 中为 NULL（诚实留空）。
3. **东财日线接口（push2his）时断时续**：`fetch_daily_history` 已实现
   腾讯 K 线回退（`web.ifzq.gtimg.cn`，空 fqt=不复权），单接口失败不阻塞
   整个 pipeline（用户要求：不要因为一个接口失败而停止 STEP 2）。

   2026-10-04 实测补充：被封时不是返回 403，而是**直接断连**
   （`RemoteDisconnected`，约 0.2s 失败），并且**会持续数分钟以上**——
   8 分钟内每 8 秒探一次全部失败。因此"每个标的都试一次主源"没有意义：
   60 个标的会得到 60 次同样的失败。现在**每轮只试一次**，失败后本轮
   全部走腾讯；`AkShareMarketProvider.eastmoney_blocked` 记录原因，
   `refresh_live_prices.py` 把它写进 `live_prices.json`，并且每次抓到的
   每一行都带 `source` 列——**数据实际来自哪一家必须可查**，不能靠
   "我们本来打算用 EastMoney"来标注。实测同一次运行 60 个标的中
   `failed: []`、`not_newer: 60`，降级期间不丢任何数据。
4. **价格口径（重要）**：chenditc 数据集的 `$close/$open/$high/$low/$vwap`
   是 **Yahoo 调整价**，`$factor` 为调整因子，原始价 = 值 ÷ factor
   （实测：茅台 2023-12-29 close/factor = 1726.00 = 交易所原始收盘价）。
   canonical `daily_bars` 存储**原始价格**并保留 `factor` 列，
   与腾讯/东财不复权数据直接可比（交叉验证平均相对差 ~3e-8）。
5. **volume/amount 都带源侧缩放（重要，别当成真实单位）**：
   chenditc 数据集的 volume 与 amount **都不是**真实股数 / 真实成交额，
   两者各有一个**每股常数**缩放（跨股差约 230×，Yahoo 伪影）。
   canonical 层的这两列**原样保留、永不修改**。

   要用的时候走校准表 `data/parquet/market/market_scale.parquet`
   （`scripts/calibrate_market_scale.py` 生成，以腾讯 K 线为 ground truth）：

   ```
   volume_shares = volume × scale_volume
   amount_cny    = amount × scale_amount          # scale_amount 缺失时
                 = volume_shares × close          # 退回这一支
   ```

   因子引擎用的就是 `volume_shares` / `amount_cny`（`factors/base.py`）。
   **不要**直接从 canonical 的 `amount` / `volume` 推股数或成交额 ——
   量级会差两三个数量级（茅台实测 amount 缩放约 ×0.011）。
   详见 `docs/步骤4-市场数据质量.md`。
6. **上市日期**：来自上交所/深交所官方列表（非快照/qlib 起始日）；
   qlib-only 的退市股票 list_date=NULL（不伪造）。
7. **代理**：本机 Windows 系统代理（127.0.0.1:7890）间歇拒绝连接；
   `personal_quant.config` 默认直连（`PQ_USE_SYSTEM_PROXY=1` 可切回）。
8. **礼貌抓取**：单连接、随机 1-3s 延迟、指数退避、所有原始响应缓存到
   `data/raw/`（支持离线重跑）。无高并发、无绕过 WAF、无代理池。
9. **当日日线 overlay（2026-10-12）**：上游快照的最新数据是 **T-1**（含 T
   的 release 次日 00:40 左右才发），导致当天晚上只能拿 T-1 的排名去配
   T+1 的成交价。现在 `scripts/quant/update_daily_overlay.py` 用**批量行情**
   补齐当日 bar，写在 **`data/parquet/overlay/`**（不写 canonical 原文件），
   由 `daily_bars` 视图与特征 provider 合并读取。

   实测（2026-10-12 20:37 CST，收盘后）：

   | 源 | 批量能力 | 全市场耗时 | 结论 |
   | --- | --- | --- | --- |
   | **qt.gtimg.cn** | 900 只/请求 | **约 15 秒 / 12 次请求** | **采用** |
   | hq.sinajs.cn | 800 只/请求 | 约 3 秒 | 仅作交叉核对 |
   | push2.eastmoney.com | 不定 | — | ❌ 当天从 pz=5 到 pz=6000 全部直接断连 |
   | push2his / fqkline | 逐只 | 45 分钟以上 | ❌ 且约 200 次请求后限流 |

   **逐只抓取被明确排除**（数千只 × 单连接 = 1.5~2.5 小时），批量是硬要求。

   字段口径（均已与 canonical 实测核对，不是照文档假设）：

   - `close/open/high/low` 是**原始价（元）**，0.01 档。2026-10-09 对 229 只
     抽样与 canonical 逐位比较：中位相对差 3e-8，**最大 0.0**。
   - `prev` 在**除权除息日**是交易所的**除权除息参考价**，不是昨收。
     2026-10-12 实测 5,564 只中 15 只如此，全部命中当日公司行为
     （股票简称带 `XD`/`DR` 前缀，例如 688110.SH canonical 的 T-1 收盘
     104.38、参考价 69.65，比值 1.4986 = 10 送 5）。
     因此 `close/prev − 1` **本身就是复权后的真实收益**。
   - `volume`（字段 6）单位是**手**；`amount`（字段 37）单位是**万元**。

   **复权桥接**：canonical 存原始价 + `factor`（`adjusted = raw × factor`），
   而模型吃的是 adjusted，所以要把 T 日接到 T-1 的复权序列上：

   ```
   A(T-1) = close_canonical(T-1) × factor_canonical(T-1)
   r      = close_live / prev_live − 1
   A(T)   = A(T-1) × (1 + r)
   factor(T) = A(T) / close_live          # 其余价列原样透传
   ```

10. **volume 的缩放其实与 factor 耦合（对第 5 条的重要修正）**：
    第 5 条说 volume 是"每股常数缩放"——只在**两个除权日之间**成立。
    实测（600519.SH，183 个交易日）：

    ```
    canonical_volume(t) = C(sym) × 真实股数(t) / factor(t)
    ```

    `C` 才是那只股票的常数。600519.SH 在 2026-06-26 除息，`factor` 涨
    2.3667%，而 volume 比率**恰好跌 1/1.023667** —— 六位有效数字完全吻合。
    所以：

    - **不要**直接用 `market_scale.scale_volume` 当今天的成交量锚点：
      它是窗口内 `factor/C` 的**中位数**，跨了多个除权平台。实测按它
      还原的误差中位 1.1%、**p90 20%、最大 207%**，21% 的标的会带着
      超过 5% 的 volume 误差进 VMA/VSTD/VSUM。
    - 正确做法是还原 `C`：

      ```
      C(sym) = median_窗口(factor) / scale_volume(sym)
      canonical_volume(T) = C(sym) × 真实股数(T) / factor(T)
      ```

      已对 600519.SH / 000002.SZ / 688110.SH 逐位验证（误差 ≤ 0.0008%）。
    - `amount` 同理：`canonical_amount ≈ U(sym) × canonical_volume ×
      canonical_vwap`，`U` 为每股常数（实测 CV 约 0.008，残差来自源侧
      自身取整）。Alpha158 **不读 `$amount`**，但 `build_universe` 的
      流动性门槛用的是它 20 日均值，所以要写、但可以容忍近似。
    - 标定表没覆盖的标的（2026-10-12 有 362 只，多数是北交所新股），
      **价格照常精确，volume/amount 写 NaN**——宁缺毋假。

11. **当日行情搞两个源（2026-10-14）**：原来只有腾讯一家，它挂了当晚就
    没有排名。加新浪做备用，**按 chunk 回退**（一个源抖了不会丢掉另一个
    源已经拿到的部分）。

    接第二个源立刻逼出一个 bug：两个源在 **621 只**标的上成交量差 100 倍。
    查下去是**我们自己的腾讯解析器**错了 ——

    > **腾讯的成交量字段：科创板 688/689 报的是「股」，其余板块报的是「手」。**

    证据是成交额：两个源对 688001.SH 的成交额完全一致（6.494e8 元），
    而「成交额 ÷ 收盘价 ≈ 1.17e7 股」与新浪的 12,123,933 吻合、与
    `字段6 × 100` 差两个数量级。10-12 起统一乘 100，于是 617 只科创板
    标的的 volume 大了 100 倍。已修（`providers/batch_quote.py`
    `_volume_unit`）。影响已量化，见
    `reports/当日日线overlay-修复信号日滞后.md` §六之四：
    10-13 信号 Top-20 只换了 1 只，且那只科创板标的本账户买不了
    （需 50 万日均资产），**交易计划未变**，冻结实验的账本一字未动。

    两源等价性（同场 session 各建一遍，逐位比）：价格 99.9% 完全相同、
    最大相对差 9.4e-07；factor 比值 1.00000000；volume/amount 比值中位
    1.00000000、p01–p99 在 5e-5 内；**只在一方出现的 0 只**。
    唯一剩下的 100 倍离群是 4 个指数伪标的（指数没有"股数"这回事，
    且已被 `config index_exclude` 挡在因子股票池之外）。

    **出口统一成真实单位（股 / 元）**，`手`、`万元` 的换算收在解析器
    内部。以前那个 `volume_lots` / `amount_wan` 的约定正是上面这个 bug
    的温床：单位藏在字段名里，谁忘了换算就错 100 倍。

    还有一道：新浪会一直供应**退市股最后一次成交**的快照
    （000004.SZ 国华退 的戳是 20260713，四个价格全非零、能通过
    "是不是停牌"的检查），所以按"行情自称的 session"过滤，不一致的丢掉。
