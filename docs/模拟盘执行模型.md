# 模拟盘执行模型 — T+1 开盘，真实约束

## 时间纪律（§8）

```
T 日收盘  →  生成信号
T+1 开盘  →  成交
```

**禁止 T 收盘信号 + T 收盘成交。** 那不是回测，那是偷价。

`paper_live/execution.py::execute_orders` 把订单交给
`personal_quant.strategy.execution.execute_order`（strategy_v1/6 复用同一实现），
由它按 signal_date 找 T+1 的开盘价。

## 不能成交的情况

一律 `NO_TRADE` 并记录原因：

| 原因 | 触发 |
|---|---|
| `no T+1 bar (suspended/halted)` | T+1 无行情（停牌） |
| `limit up` | 买入时 T+1 开盘 ≥ 昨收 × 1.095 |
| `limit down` | 卖出时 T+1 开盘 ≤ 昨收 × 0.905 |
| `no prev close` | 信号日无行情，算不出涨跌停 |
| `zero shares` | 股数为 0 |
| `below one lot` | 差额不足 1 手 |

> 涨跌停阈值 `0.095` 是**制度近似**（10% 涨跌停制），不是精确的
> ST/科创板 ±5% / ±20% 规则。沿用 strategy_v1 的既有约定，未修改。

## 先卖后买

`execute_orders` 显式把 SELL 排在 BUY 前面。

不做这个排序的话，按代码顺序执行时中间现金会变成负数 —— 现实中卖出
释放的资金本来就可以立刻用于买入。

## 手数：理论 ≠ 实际（§10）

```
target_value             目标金额 = 目标权重 × 组合市值
delta_value              本次要动多少钱 = target_value − current_value
theoretical_shares       = target_value / price（未取整）
estimated_shares         向下取整到 100 股整数倍
estimated_trade_value    = |estimated_shares| × price
estimated_fee            预估费用
```

每一笔订单都同时记录这些数（`PlannedOrder.as_row()`），
**绝不把理论权重当成实际执行权重**。

> 因取整而未投出的钱**没有单独字段**，需要时自己算
> `delta_value − estimated_trade_value`。
> （原文写的 `residual_cash` 列并不存在 —— 那个名字只出现在模块 docstring 里，
> 2026-10-05 一并更正。）

清仓是精确的：持仓本来就是整手，`target_weight = 0` 时卖出全部股数，
不会留下零股。

## 当前市值按市价算

一个曾经写错的地方：`build_orders` 里计算持仓当前价值时，必须用
**当日市价**，不能用上次成交价（= 成本）。用成本会把 `delta_value`
算错，进而超买/超卖，现金被打成负数。

## 成本模型

与 `strategy_v1` **完全同一套**（禁止第二套费率）：
佣金 0.025%（最低 5 元）+ 印花税 0.05%（卖出）+ 过户费 0.001% + 滑点 0.05%。

`tests/forward/test_transaction_cost.py` 断言 paper live 用的模型与
strategy_v1 的参数逐项相等。

## 挂单

当天收盘后运行时 T+1 尚未开盘 → 订单挂起，下次运行按 T+1 开盘价成交。
详见 `docs/模拟盘实验.md`。
