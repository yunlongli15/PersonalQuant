# 策略冻结 — 能证明它没变

冻结不是把文件设成只读，而是**能证明它没变**。

## 冻的是什么

`config/paper_live.yaml` 的 `freeze` 块记录以下工件的 sha256：

| 键 | 文件 |
|---|---|
| `paper_live_config` | `config/paper_live.yaml`（**freeze 块以外**的内容） |
| `model` | `experiments/news/strategy/model.txt`（S3 生产模型） |
| `model_params` | `config/strategy_v1.yaml`（LightGBM 参数） |
| `universe_config` | `config/strategy_v1.yaml`（股票池规则） |
| `feature_pack_0/1` | `factor_pack_v1.json` + `factor_pack_news_v1.json` |

每次运行都重算并比对。不一致 → `DRIFT_DETECTED` → 该日
**不得作为 clean forward observation**。

## 一个必须避免的坑：自指

如果 `paper_live_config` 的哈希把 freeze 块也算进去，那么"写入 freeze"
这个动作本身就会改变哈希，下一次校验必然报 drift。

所以 `config_sha256()` 先在文本上剥掉 freeze 块再算哈希：
**冻结的是 freeze 块以外的内容**。

## 冻结用哪个策略，为什么（spec §4）

冻结对象是 `strategy_v2`，依据是**已有的冻结状态，不是重新优化**：

1. 它是系统自己的既有指定 —— 只有 `config/strategy_v2.yaml` 带
   `paper_live` 块（capital 500000）；`pipeline/signals.py` 也把 S3
   称为 "the FROZEN production model"。
2. alpha = **S3**（Alpha158 + factor_pack_v1 + news）在 STEP 5 通过了
   research+validation 的增量检查（D > B）。
3. allocation = **equal_weight**，由 STEP 6 的研究期 + 验证期选出
   （没有任何优化器在 research+valid 上超过等权）。
4. strategy_v2 的 candidate gates **有 2 项未通过**，但两项都在
   **frozen test 2024-2025** 上。spec §4 明令不得依据 test 结果重新选择——
   用它去否掉，与用它去选中，同样违规。因此原样保留为已知 caveat。

> 已知 caveat：
> - `2_validation_pass` FAIL：门槛是"绝对收益 > 0"，2022-2023 熊市中
>   策略绝对收益 −12.90%（CSI300 −16.61%，相对 IR 0.305）。门槛不因
>   结果不利而重写。
> - `9_no_pathological_concentration` FAIL：P0 等权不施行业上限
>   （锚点可复现的前提），行业集中度可达 ~40%。属已知基线属性。

## 冻结只做一次

```bash
python scripts/paper_live/freeze.py          # 写入哈希
python scripts/paper_live/freeze.py --check  # 只校验
```

`freeze.py` 在发现"已经冻结但哈希不一致"时**拒绝重新冻结**并返回码 2。
确需变更时应当新开 `strategy_version` 与新的 forward holdout，并在报告中
记录原因 —— 而不是覆盖旧哈希。
